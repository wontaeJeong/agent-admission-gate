## 검사 계약

실행 상태는 PENDING → RUNNING → COMPLETED / FAILED / CANCELLED입니다. COMPLETED가 반입 허용을 의미하지는 않습니다. 최종 반입은 `effective_verdict`로 판단하세요. 원래 엔진 판정은 `verdict`에 보존됩니다.

Static은 내장 소스 규칙과 감지된 Skill/MCP 메타데이터를 검사합니다. Full은 Syft SBOM, Grype CVE, Grant 라이선스, 설정된 모델을 추가하고 OSV는 선택적으로 켭니다. 원본 코드나 대상 MCP 도구를 실행하지 않습니다. 대형·비텍스트 파일 또는 결과 절단은 불완전 범위로 표시합니다.

같은 사용자·내용 해시·프로필·정책/엔진 설정의 완료된 검사만 TTL 내 재사용합니다. Git은 먼저 실제 체크아웃을 수행하므로 변경된 브랜치 내용을 과거 URL 캐시로 통과시키지 않습니다. 개인 인증정보는 캐시 키나 저장 데이터에 포함하지 않습니다. `force_rescan=true`로 캐시를 건너뜁니다. 업로드 파일은 다시 업로드하고 Git은 URL을 재접수합니다.

## 사람의 검토

검사 소유자만 검토 요청을 만들 수 있습니다. user/admin 역할과 reviewer 자격은 별도입니다. 관리자가 자동으로 검토자가 되지는 않습니다. 본인 요청 승인, 이미 결정된 요청 변경, 필수 검사 미완료 승인은 차단합니다. 승인/반려 사유와 원래 판정을 보존합니다.

일반 사용자는 자신의 검사·요청만 조회합니다. 검토자는 검사 근거와 검토 대기열에 접근할 수 있지만 사용자 권한이나 전체 API 키를 관리할 수 없습니다. API 키는 소유자 범위의 scan:read/write만 가능하며 관리·승인 기능을 호출할 수 없습니다.

## 예외

관리자는 소스 식별자, 내용 SHA256, 발견 fingerprint, 사유, 최대 90일 만료를 지정합니다. 다른 내용이나 다른 소스에는 적용되지 않습니다. 예외는 다음 검사에서 적용되고 원래 발견 항목은 suppressed로 보존합니다. 이미 발급된 결과를 실시간 재인가 토큰으로 사용하지 마세요.

검토 승인이나 예외로 제한된 위험을 허용할 수는 있지만, 누락된 엔진을 성공한 것으로 바꾸지는 않습니다. 취약점 DB·정책이 변경되면 엔진 revision을 올리고 재검사해야 합니다.
